# Журнал съёмки

Два инструмента для съёмки, где оператор один, а рилсов за день больше десяти:

- `app/` — веб-приложение для iPhone (PWA). На площадке отмечаешь рилс, дубль и оценку.
- `tools/sort_shoot.py` — скрипт для ПК. По журналу раскладывает видео и звук по рилсам и дублям, делает HTML-отчёт и JSON для сборки монтажа.

## Приложение

### Установка на iPhone
1. Открой адрес приложения в Safari.
2. «Поделиться» → «На экран "Домой"».
3. Запусти с иконки один раз при интернете — дальше работает без сети.

Данные лежат только в телефоне (IndexedDB), пока не сделан экспорт.

### До съёмки
- «+ Рилс» — карточка: название, кто в кадре, текст.
- «+ Списком» — много рилсов сразу: одна строка = один рилс, после «/» — кто в кадре. Удобно диктовать (микрофон на клавиатуре, «новая строка»).
- «Ещё → Импорт рилсов из JSON» — список можно подготовить на ПК: `["Название 1", "Название 2"]` или `{"reels":[{"title":"…","cast":"…","text":"…"}]}`.

### На площадке
1. **Калибровка часов (один раз в начале, каждой камерой).** «Часы» → сними экран телефона 3–5 секунд. В кадре должен быть QR целиком.
2. Открой рилс. Нажми большую кнопку **«Дубль»** в момент старта камеры.
3. После дубля одно нажатие: **Хороший / Запасной / Брак**. Если некогда — «Сразу следующий дубль», оценку можно поставить позже.
4. По желанию: «Голос», «Фото», «Текст» — заметка к последнему дублю.
5. «Отменить» — откатывает последнее действие (дубль, оценку, заметку).

Звук: если пишешь Диктофоном на этом же iPhone, голосовую заметку делай после остановки Диктофона — iOS отдаёт микрофон одному приложению. Вариант: «Ещё → Звук дубля пишет приложение» — запись стартует по «Дубль» и останавливается по оценке; экран при этом гасить нельзя.

### После съёмки
«Экспорт» → меню «Поделиться» → Telegram «Избранное», iCloud Drive или почта. Получится `journal_ДАТА.zip`: `journal.json` и папка `media/` с заметками.

## Скрипт разбора

Нужны Python 3.10+, ffmpeg/ffprobe в PATH и пакеты:

```bash
pip install numpy opencv-python-headless
```

Запуск:

```bash
python tools/sort_shoot.py --cam "F:/съёмка/Cam" --sound "F:/съёмка/Sound" --journal journal_2026-11-20_1830.zip --out "E:/съёмка/report"
```

Исходники только читаются. В папке `--out` появятся:

- `report.html` — отчёт по рилсам: дубли, оценки, превью, какой звук к какому клипу, заметки;
- `edit.json` — то же для сборки монтажа (пути, длительности, `audio.lag`: время записи = время клипа + lag);
- `rename_plan.csv` — план имён `R03_T02_OK__itsalive0004.MP4`;
- с ключом `--layout copy` (или `hardlink` на том же диске) — папка `by_reel/` с разложенными файлами.

### Как скрипт сопоставляет

| Что | Как |
| --- | --- |
| Сдвиг часов камеры | 1) QR с экрана «Часы» в первых секундах любого клипа (точность — кадр); 2) если QR нет — автоматически по рисунку интервалов между нажатиями «Дубль» и стартами клипов; 3) вручную `--offset СЕКУНДЫ` |
| Клип → дубль | Ближайшее нажатие «Дубль» в пределах `--tol` (8 с) или попадание внутрь дубля |
| Звук → клип | Кросс-корреляция огибающей; остальные клипы внутри той же записи привязываются по часам камеры |
| Клипы без отметки | С `--transcribe` ищется слейт «рилс N, дубль M» в расшифровке |

Несколько камер — несколько `--cam`, у каждой свой сдвиг (и своя калибровка).

Полезные ключи: `--no-qr` (не искать QR), `--transcribe` (расшифровка через `npx hyperframes`, локально), `--transcripts ПАПКА` (готовые расшифровки `<имя>.json`), `--no-thumbs`.

### Слейт без приложения
В начале дубля скажи: **«Рилс три, дубль два»** и хлопни. Скрипт понимает цифры и слова («рилс двадцать один, дубль первый»), слова «ролик», «тейк». Расшифровка иногда принимает пение за речь, поэтому слейт ищется только как связка «рилс + число + дубль + число» в пределах 8 секунд.

## Что важно знать про исходники

- У записей Диктофона iPhone время создания файла — это время экспорта, а не записи. Поэтому звук привязывается по содержимому, а не по времени.
- Время клипа берётся из `creation_time` (точность 1 с) и уточняется по таймкоду, если он идёт синхронно с часами (Free Run).
- Совет по камере: выставь дату и время, включи таймкод Free Run. Тогда время в файлах осмысленное, а калибровка по QR даёт точность до кадра.

## Проверка

- Съёмка из 51 клипа и 15 записей: сдвиг часов найден автоматически, 16 из 16 дублей разложены верно, 15 из 15 известных пар «звук ↔ видео» совпали.
- Синтетический клип с QR: ошибка сдвига 3 мс.
